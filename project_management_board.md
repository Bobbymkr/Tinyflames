# Tiny Flames — Project Management Board Plan

**Project:** Tiny Flames Custom Candle Brand Website  
**Purpose:** To manage website development smoothly using a structured board  
**Recommended Tools:** Trello / ClickUp / Notion / Asana / Jira  
**Board Style:** Kanban + Sprint-based execution  
**Project Focus:** Premium custom candle website with international trust, emotional gifting, and WhatsApp-first support

---

# 1. Board Objective

This board will manage the complete Tiny Flames website project from:

1. Discovery and validation
2. Brand and content collection
3. UX/UI design
4. Development
5. Integrations
6. QA testing
7. Client approval
8. Launch
9. Post-launch optimization

The board should prevent:
- Missing tasks
- Unclear ownership
- Scope confusion
- Development delays
- Client approval bottlenecks
- Unvalidated assumptions

# 3. Workflow Meaning

## 📥 Backlog
All planned tasks that are not yet scheduled.

## 🎯 Discovery & Validation
Tasks related to confirming business, product, operations, and technical requirements.

## 🧭 UX & Wireframes
Sitemap, user flows, wireframes, page structure.

## 🎨 UI Design
Visual design, design system, page mockups, client design approval.

## 🧱 Development
Actual frontend/backend/theme development.

## 🛒 E-commerce & Integrations
Payment, shipping, WhatsApp, analytics, email, reviews, customizer tools.

## 🧪 QA & Testing
Functional testing, mobile testing, browser testing, speed, security.

## 👀 Client Review / UAT
Client checks and approves completed work.

## 🚀 Launch Preparation
Final launch readiness, live testing, launch-day tasks.

## ✅ Done
Fully completed, tested, and approved tasks.

## ⛔ Blocked / Waiting on Client
Tasks waiting for client input, assets, approval, or external dependency.

# 6. Project Phases

## Phase 0: Project Setup & Discovery
Goal: Confirm everything before design or development begins.

## Phase 1: UX & Design System
Goal: Create wireframes and visual design language.

## Phase 2: Core Website Build
Goal: Develop global layout, homepage, shop, and product pages.

## Phase 3: Customization & Checkout
Goal: Build customizer, cart, checkout, and order flows.

## Phase 4: Trust, International & Automation
Goal: Add international clarity, WhatsApp, automations, reviews, SEO, analytics.

## Phase 5: QA, Client Approval & Launch
Goal: Test everything, get approval, and launch.

# 10. Definition of Ready

A task can move into development only if:

- [ ] Requirement is clear
- [ ] Design is approved
- [ ] Content/assets are available
- [ ] Dependencies are identified
- [ ] Owner is assigned
- [ ] Priority is set
- [ ] Acceptance criteria are written

---

# 11. Definition of Done

A task can be marked done only if:

- [ ] It is built
- [ ] It is tested
- [ ] It works on mobile
- [ ] It works on desktop
- [ ] Content is final
- [ ] No known critical bugs
- [ ] Client approval received where needed
- [ ] Analytics/tracking verified if applicable

---

# 12. Blocked Task Rules

If a task is blocked:

1. Move it to **⛔ Blocked / Waiting on Client**
2. Add comment explaining the blocker
3. Tag the responsible person
4. Add expected resolution date
5. Review in next daily/weekly check-in

Common blockers:
- Waiting for client approval
- Missing product photos
- Missing copy
- Missing shipping rates
- Missing payment gateway details
- Missing customization confirmation
